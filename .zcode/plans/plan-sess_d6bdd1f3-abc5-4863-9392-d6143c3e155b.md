## 修复计划：pnpm dev 前端报 access-token-only 错误

### 根因
- `iam-app-sdk` 登录类端点（`/auth/sessions`、`/oauth/sessions`、`/system/iam/*` 等）为 `accessTokenOnly`，dispatch 前要求 tokenManager 持有 Access-Token
- 开发模式下该 token 由编排生成 fixture JWT（`SDKWORK_ACCESS_TOKEN`）→ vite plugin 注入浏览器 `globalThis.__SDKWORK_CREDENTIAL_ENTRY_BOOTSTRAP_ACCESS_TOKEN__` → 水合 tokenManager
- 断点 A：browser standalone 的 adaptive web 编排启动 vite renderer 时未注入 `SDKWORK_ACCESS_TOKEN`（desktop 编排 `scripts/lib/im-pc-dev.mjs:569` 有注入，browser 无）
- 断点 B：H5 的 `vite.config.ts` 缺少 `createSdkworkCredentialEntryBootstrapVitePlugin`（PC 有，`apps/sdkwork-im-pc/vite.config.ts:261-264`），即使注入 env 也无法传到浏览器

### 修改（2 个文件，均为本仓库，对齐既有 PC 约定）

**1. `scripts/dev/run-vite-cli.mjs`（PC/H5 共用 renderer 启动器）**
- dev server 模式（`process.argv` 不含 `build`）下，在启动 vite 前调用 `mergeSdkworkImBootstrapAccessTokenEnv(process.env)`（从同目录 `./sdkwork-im-bootstrap-access-token.mjs` 导入，复用 IM 根 manifest `backend.appId=sdkwork-im-pc` 生成 development fixture JWT）注入 `process.env.SDKWORK_ACCESS_TOKEN`
- build 模式不注入（production 不得生成 dev token；vite.config.ts 中 plugin 按 mode 也不会注入）

**2. `apps/sdkwork-im-h5/vite.config.ts`（与 PC 对齐）**
- `defineConfig({...})` 改为 `defineConfig(({mode}) => ({...}))`
- 导入 `createSdkworkCredentialEntryBootstrapVitePlugin`（`@sdkwork/iam-credential-entry/vite`，node_modules 已 workspace 链接到最新源码）
- plugins 增加 `createSdkworkCredentialEntryBootstrapVitePlugin({ accessToken: process.env.SDKWORK_ACCESS_TOKEN, environment: mode })`
- resolve.alias 增加 `@sdkwork/iam-credential-entry/vite` → `../../../sdkwork-iam/apps/sdkwork-iam-common/packages/sdkwork-iam-credential-entry/src/vite.ts`（与 PC 同款源码引用）
