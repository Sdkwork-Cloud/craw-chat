## 目标

补齐服务端 Rust 网关的浏览器检测，使其与共享移动端契约（dev 代理 `@sdkwork/app-topology` `adaptive-web.mjs` 的 `MOBILE_USER_AGENT_PATTERN` + 检测顺序）完全一致：**移动端浏览器（含微信/鸿蒙/UC/Quark/华为浏览器）在请求时稳定获得 H5 应用资源，桌面端获得 PC 资源**。不改客户端应用。

## 改动文件

### 1. `crates/sdkwork-api-product-runtime/src/web_client_routing.rs`

- 扩展 `MOBILE_USER_AGENT_MARKERS`：新增 `micromessenger`、`huaweibrowser`、`harmonyos`、`ucbrowser`、`quark`；移除 `ipad`（iPad 按契约默认桌面端，与 dev 代理 `tablet: 'pc-web'` 默认一致）。
- `preferred_web_client` 增加 `sec_ch_ua_mobile: Option<&str>` 参数，判定顺序镜像 JS 契约：
  1. `Sec-CH-UA-Mobile` 请求头 trim 后 == `"?1"` → H5
  2. UA 含 `ipad` → Pc（tablet 默认 pc-web）
  3. UA（小写）命中移动标记 → H5
  4. 否则 → Pc；缺 UA → Pc
- `select_available_web_client` 透传该参数，保留双向 fallback（h5 缺失→pc，pc 缺失→h5）。
- 更新/新增单元测试：微信 `MicroMessenger`、`HarmonyOS`、`UCBrowser`、`Quark`、`HuaweiBrowser`、`Android Mobile` → H5；iPad UA（含 `Mobile` 字样）→ Pc；`sec-ch-ua-mobile: "?1"` + 桌面 UA → H5；Windows → Pc；`None` → Pc；双向 fallback 不变。

### 2. `crates/sdkwork-api-product-runtime/src/lib.rs`

- `select_request_site_dir`（约 506 行）：读取 `sec-ch-ua-mobile` 请求头并传入 `select_available_web_client`。
- `apply_user_agent_vary`（约 526 行）：`Vary: user-agent, sec-ch-ua-mobile`（两个输入信号都影响响应选择）。
- 测试辅助：新增 `fetch_response_with_headers(base_url, path, headers)`（现有 `fetch_response_with_user_agent` 委托给它）。
- 新增端到端用例 `router_runtime_detects_mobile_clients_matching_the_shared_contract`（沿用 `TestSiteDir`/`start_runtime` 模式）：
  - 微信 UA（`MicroMessenger`）→ `h5-shell`
  - `HarmonyOS` / `UCBrowser` / `Quark` / `HuaweiBrowser` UA → `h5-shell`
  - iPad UA（`Mozilla/5.0 (iPad; ...) Mobile/15E148`）→ `pc-shell`
  - 桌面 UA + `Sec-CH-UA-Mobile: ?1` → `h5-shell`，且响应 `Vary` 含 `sec-ch-ua-mobile`
- 更新现有两处 `Vary == "user-agent"` 断言（约 1236/1248 行）为 `"user-agent, sec-ch-ua-mobile"`。

- 客户端两个应用（`apps/sdkwork-im-h5`、`apps/sdkwork-im-pc`）— 用户选择仅服务端。

- `specs/im-web-ingress-domain.spec.json`（已声明 `selection: "user-agent"`、`mobileClient: "h5"`，不含标记明细）与文档。

## 行为变更说明

- iPad 用户从 H5 变为 PC 渲染器（与 dev 代理现有行为、共享契约对齐）。
- 微信/鸿蒙/UC/Quark/华为浏览器用户由 PC 资源修正为 H5 资源（本次修复的核心）。
