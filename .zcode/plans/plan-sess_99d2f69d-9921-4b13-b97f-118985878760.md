## 背景（已查明的根因，双重问题）

1. **端口冲突（当前主因）**：WSL 里 Docker 容器 `sdkwork-im-docker-im-gateway-1` 映射 `0.0.0.0:18079`，经 WSL2 localhost 转发在 Windows 侧形成"幽灵监听"（netstat 不可见、bind 报 EADDRINUSE、但能 accept 连接）。Windows `pnpm dev` 网关无法绑定 18079。
2. **工具链缺陷（本次报错直接原因）**：`scripts/gateway-standalone-run.mjs:143` 强制 `maxAttempts: 1`（探测失败即退出）；`stopOwnedBindings`（sdkwork-app-topology）在 dev `finally` 中抛错，掩盖了主启动错误（日志里只剩 "owned TCP bindings remain occupied by PID(s): 9148"）；陈旧进程清理按 exe 名 taskkill 且静默吞失败。

**用户决策**：修改本地 `pnpm dev` 端口避开冲突；Docker 端口 18079 保持不变。

## 实施计划

### 一、本地 dev 网关端口 18079 → 18089（Docker 及生产/测试/暂存配置不动）

新端口 **18089**（已实测：Windows 18050-18150 扫描仅 18079 被占，18089 可绑定；WSL 侧 1808x 段仅 18079 有监听）。实施前再验证一次并全局 grep 无冲突。

**1. 权威配置（etc/）**
- `etc/topology/standalone.development.env`：`SDKWORK_IM_APPLICATION_PUBLIC_INGRESS_BIND=0.0.0.0:18089`、HTTP_URL/WEBSOCKET_URL、VITE_* 全部改 18089（仅此一个 profile 文件；production/staging/test 保持 18079）。

**2. dev 流程代码默认值（6 处）**
- `scripts/dev/sdkwork-api-im-standalone-gateway-dev-runtime.mjs`：`DEFAULT_GATEWAY_PORT = 18079` → `18089`
- `scripts/lib/im-pc-vite-dev-env.mjs:17`：`DEFAULT_DEV_GATEWAY_START_PORT` → 18089
- `apps/sdkwork-im-pc/packages/sdkwork-im-pc-core/src/sdk/runtimeGatewayDiscovery.ts:8`：探测起始端口 → 18089（避免渲染端回退探测误连 Docker 网关）
- `apps/sdkwork-im-pc/scripts/sdkwork-im-iam-env.mjs:16-18`：本地默认 URL → 18089
- `scripts/lib/im-pc-dev.mjs:142`（默认 URL）+ 708（日志文案）
- `scripts/dev/ensure-im-h5-demo-users.mjs:26`：`DEFAULT_BASE_URL` → 18089

**3. 客户端 env**
- `apps/sdkwork-im-pc/.env.standalone.development`、`.env.example`：VITE 三处 URL → 18089

**4. 明确不改**
- `deployments/docker/*`、WSL compose（18079 保持）
- `crates/sdkwork-api-im-standalone-gateway/src/main.rs:15`（Rust 默认绑定，供所有 profile 兜底）
- `specs/topology.spec.json:29` gatewayBind 默认、`etc/topology/standalone.{test,staging,production}.env`
- 渲染端若存在其他 18079 硬编码仅限 dev 流程者，逐一核对后同步

### 二、启动工具链加固（实现并优化）

1. **`scripts/gateway-standalone-run.mjs`**：删除 `maxAttempts: 1`（恢复默认 50 探测回退）；端口发生回退时输出明确日志（`[sdkwork-api-im-standalone-gateway] 18089 unavailable, using ...`）；把网关 bind 端口传给陈旧进程清理。
2. **`scripts/dev/terminate-stale-dev-gateway-processes.mjs`**：taskkill 失败不再静默（输出 stderr/status）；新增按端口查 LISTENING PID 并 `taskkill /F /PID`；清理后校验端口已释放（有限重试）。同步更新其测试。
3. **`sdkwork-app-topology/tools/topology/lib/development-ownership.mjs`** `stopOwnedBindings`：win32 下 SIGTERM 无效后升级 `taskkill /F /PID`；总宽限从 ~1s 提升到 ~5s；保持依赖注入以便测试。
4. **`sdkwork-app-topology/scripts/sdkwork-app.mjs`**（dev finally）：`stopOwnedBindings` 失败降级为警告日志，不再掩盖主启动错误（`stop` 命令路径保持抛错语义）。
5. **`sdkwork-api-im-standalone-gateway-dev-runtime.mjs`**：全部候选端口失败时，错误信息附带首端口诊断（netstat 有无 LISTENING PID；无监听但 connect 成功 → 提示 WSL2/Docker 端口镜像），依赖注入保持可测。
