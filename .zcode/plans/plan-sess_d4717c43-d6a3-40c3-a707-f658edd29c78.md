## 诊断结论（已线上复现）

`410 Gone` 不是 vite 发出的，而是 **sdkwork-app 自适应开发代理**（sibling 仓库 `sdkwork-app-topology/tools/topology/lib/adaptive-web.mjs`）发出的：代理在 3801 端口按设备 UA 把请求路由到 pc-web (vite:4176) 或 h5 (vite:4178) renderer，对任何 `/node_modules/.vite/*` 请求，若其 cache 路径与"当前优选 renderer"的 label 前缀不匹配，就直接返回 410。

**已实测**：桌面 UA 请求 `/node_modules/.vite/sdkwork-im-pc/deps/react.js?v=6b38b4ba` → 200；手机 UA 同 URL → 410。当前 h5 renderer 已挂死（进程存活、CPU≈0、所有请求挂起），当路由落到错误 renderer 时，页面缓存的 main.tsx 依赖（react/react-dom/jsx-dev-runtime，即用户报错的三行）全部 410。

加剧因素（sdkwork-im 仓库内）：
1. 两个 app 的 vite `cacheDir` 都在 `node_modules/.vite/...` 内，而本工作区存在 `ensureLocalNodeModules` 的 node_modules 整体改名/junction 交换机制（残留 `node_modules.__stale__donor*`），缓存随时可能被抹掉 → 中途重新优化 → 旧 hash 失效。
2. pc 的 `optimizeDeps.include` 只有 `dompurify`，monaco/radix/react-syntax-highlighter 等 70+ 依赖都是运行时才发现 → 运行途中触发重新优化。
3. `apps/sdkwork-im-h5/node_modules` 是指向 pc `node_modules` 的 junction（共享同一物理目录），拓扑脆弱。

## 修复方案

### A. sdkwork-im 仓库（本次主修）

1. **`apps/sdkwork-im-pc/vite.config.ts`**：`cacheDir` 从 `node_modules/.vite/sdkwork-im-pc` 改为 `path.resolve(__dirname, '.vite')`（移出 node_modules）。dep URL 变为 `/.vite/deps/...`，不再落入代理的 `/node_modules/.vite/` 410 检查范围，且 node_modules 交换/pnpm 重装不再抹缓存。
2. **`apps/sdkwork-im-h5/vite.config.ts`**：同样改为 `path.resolve(__dirname, '.vite')`。
3. **两个 app 的 `.gitignore`**：新增 `.vite/`。
4. **两个 app 的 `_sdkwork:clean`**：清理 `dist` 的同时清理 `.vite`。
5. **`apps/sdkwork-im-pc/vite.config.ts` `optimizeDeps.include`**：按当前缓存元数据补全运行时发现的依赖（`@monaco-editor/react`、`@radix-ui/react-*` 18 个、`@tanstack/react-table`、`@tauri-apps/api/*`、`@tiptap/*` 与 `tiptap-markdown`、`react-syntax-highlighter` 及其 prism 子路径、`rehype-raw`、`remark-gfm`、`signature_pad`、`qrcode`、`react-resizable-panels`、`sonner`、`react-day-picker`、`cmdk`、`html2canvas*`、`jspdf`、`marked`、`motion/react`），启动时全部预打包 → 中途不再重新优化。

### B. sdkwork-app-topology 仓库（410 直接发射源，已获你确认）

6. **`tools/topology/lib/adaptive-web.mjs` `proxyRendererRequest`**：`/node_modules/.vite/<label>/` 请求按 cache 归属 renderer 路由（label 匹配优先于设备分类）：
   - 归属 renderer 就绪 → 转发给它（手机 UA 请求 pc 缓存也正确转发 → 消除本次 410）；
   - 归属 renderer 不可用或无归属 → 保持原 410（"reload the browser page" 语义不变）；
   - 非 cache URL 走原设备分类逻辑（行为不变）。
7. **`tests/adaptive-web.test.mjs`**：补充两个用例——桌面 UA 请求 h5 归属缓存路径应路由到 h5（不再 410）、手机 UA 请求 pc 归属缓存路径应路由到 pc。

### C. 环境清理（已获你确认）

8. 删除残留 `node_modules.__stale__donor*`（pc 下 2 个、h5 下 1 个；junction 仅删链接本身，先 `du -sh` 报告体积）。
9. 报告：需重启 `pnpm dev` 会话使配置生效并恢复挂死的 h5 renderer（我不代劳杀进程）。
