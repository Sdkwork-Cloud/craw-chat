# Welcome 消息功能实现计划

## 需求
注册/登录 IM 时确保用户收到系统智能体的 Welcome 系统消息，**不重复发送**：
- 已收到过 Welcome → 跳过
- 已与其他人有过对话（存在有消息的会话）→ 跳过
- 否则发送：`messageType=system` 的系统消息，由「系统智能体」发出
- 触发方式：AI 主动 / 人工调用 API / 注册后自动触发

## 总体设计（用户已确认）
- **会话形态**：系统智能体↔用户 **direct chat**（确定性 canonical ID，天然幂等；H5/PC/移动端收件箱原生兼容）
- **消息**：`MessageType::System` + sender `{kind:"system", id:"system"}`（代码库既有系统 actor 约定），确定性 `client_msg_id = "welcome:{user_id}"` → 消息投递本身幂等（replay 检测）
- **去重状态**：`im_user_settings` 表存 `welcome.sent`（JSONB：conversation_id / message_id / message_seq / sent_at / version）
- **「已有对话」判定**：`im_conversation_members` JOIN `im_conversations`，用户为成员且 `message_count > 0`，**排除 welcome 会话本身**（崩溃恢复不误判）

## 后端改动

### 1. 内部 RPC 契约（AI 主动 / 人工 / IAM 集成入口，mTLS）
- `apis/rpc/sdkwork/communication/internal/v1/message_dispatch_service.proto`：新增 `UserWelcomeService.SendWelcomeMessage`
  - 请求：`tenant_id, organization_id, user_id, text?`（可选覆盖文案）
  - 响应：`status = sent | already_sent | already_engaged` + `conversation_id / message_id / message_seq`
- 重新生成 RPC SDK（`buf generate`，rust + 各语言 SDK），`pnpm run test:rpc-contract` 校验

### 2. Welcome 核心逻辑（新模块）
- `services/sdkwork-comms-conversation-service/src/runtime/welcome.rs`：`ensure_user_welcome(...)`
  1. 读 `welcome.sent` → 有 → `already_sent`
  2. 「已有对话」检查（新 SQL）→ 有 → `already_engaged`
  3. 会话不存在则绑定 system↔user direct chat（`canonical_direct_chat_*` 确定性 ID，system binder 权限已支持，绑定 request-key 幂等）
  4. `post_message`（`MessageType::System`，sender system，确定性 client_msg_id → 并发/重试不重复）
  5. upsert `welcome.sent` 标记
- 配置：`SDKWORK_IM_CONVERSATION_WELCOME_MESSAGE_TEXT`（欢迎文案，默认中文）、`SDKWORK_IM_CONVERSATION_SYSTEM_AGENT_DISPLAY_NAME`（默认「系统智能体」），沿用 `std::env::var + fallback` 惯例

### 3. 持久化
- conversation 服务持久化层（postgres-journal 侧）新增 `WelcomeStateStore`：
  - `read_welcome_sent` / `write_welcome_sent`（`im_user_settings`，ON CONFLICT DO UPDATE 惯例）
  - `user_has_conversations_with_messages(tenant, org, user_id, exclude_conversation_id)`（新 SQL，表与索引已存在）
  - 配套 in-memory fake 用于测试

### 4. 内部 RPC 注册
- `internal_rpc_dispatch.rs`：service key 加 `sdkwork.communication.internal.v1.UserWelcomeService`，dispatch 加 `internal.userWelcome.send`

### 5. App HTTP 端点（H5 注册后触发 / 人工自服务调用）
- `POST /im/v3/api/chat/me/welcome/ensure`（从 auth context 取 user_id，仅限本人，幂等，fire-and-forget 安全）
- `runtime/http.rs` 路由 + handler；`apis/open-api/im/sdkwork-im-im.openapi.yaml` 新增 operation；重新生成 TS SDK（`@sdkwork/im-sdk`）

## H5 客户端改动
- **触发**：AuthGate 认证建立时（覆盖注册后首次进入与老用户登录，后端幂等自判断）及 Auth.tsx mock 注册成功后，fire-and-forget 调 ensure-welcome（通过 chatConversationService port 模式，不手写 HTTP；失败静默）
- **显示名**：收件箱/聊天标题对 `principalKind === "system"` 的 direct chat 显示「系统智能体」（i18n），避免裸显示 "system"

## 测试与验证
- `welcome.rs` 单元测试（in-memory harness，仿 `conversation_flow_test.rs`）：新用户→sent、重复调用→already_sent、已有对话→already_engaged、消息已发但标记未写（模拟崩溃）→ 恢复不重复
- HTTP 端点测试（仿 `http_smoke_test.rs`）
- 验证命令：`cargo test -p sdkwork-comms-conversation-service`、`pnpm run test:rpc-contract`、H5 相关 check

## 边界说明
- 真实注册在外部 IAM（sibling repo）：本仓库交付内部 RPC 契约，IAM 注册后调用即完成服务端集成（跨仓库联调另行安排）
- AI 主动对话：agents/automation 服务通过内部 RPC（mTLS）调用同一入口
- 人工调用：内部 RPC（运维工具）或自服务 HTTP 端点
- 不修改客户端 system 消息特殊渲染（按用户选择保持文本气泡，消息在存储/实时推送/API 契约中均为 system 类型）
