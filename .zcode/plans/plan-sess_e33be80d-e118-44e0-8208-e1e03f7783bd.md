# H5 端即时通讯能力接入完善计划

## 背景结论
H5 主链路（会话列表/消息收发/加好友/实时推送/置顶免打扰等）已走 `@sdkwork/im-sdk` 真实 API。本次补齐 PC 端已有而 H5 缺失/占位的能力，**所有现有 UI 视觉与交互保持不变**，仅按原风格最小增补缺失功能入口，全部走生成 SDK（禁止裸 HTTP）。

## 一、发送消息补齐（图片/视频/文件真实发送）
- `ChatActionPanel` 7 个按钮当前传假 URL → toast。接线方案：
  - `ChatDetail.tsx` 的 `handleSendCustom` 按 type 触发隐藏 `<input type="file">`（image→`accept=image/*`、video→`video/*`、file→`*`），选中文件后走**已接线的真实链路** `sendMedia`（Drive 上传 → `conversations.postMessage` media part），UI 按钮视觉不变
  - music/link/miniapp/call 无后端能力，保持 toast 不可用（与现状一致）

## 二、消息操作补齐（撤回/编辑）
- SDK 已有 `messages.recall` / `messages.edit`，H5 未暴露。步骤：
  1. `ChatService.ts` 扩展 `ChatSdkPort` + 实现 `recallMessage(conversationId, messageId)`、`editMessage(conversationId, messageId, text)`（编辑沿用 replyTo 结构的 body）
  2. `MessageContextMenu.tsx` 按原视觉增补菜单项：「撤回」（仅本人消息，onClick → recall → 本地刷新消息状态）、「编辑」（仅本人 text 消息，弹出轻量输入框 → edit → 本地更新）。复制/回复/收藏/删除保持不动

## 三、会话 profile 管理补齐
1. `ChatService` 新增 `updateChatProfile(conversationId, {displayName?, avatarUrl?, notice?})` → `conversations.updateProfile`（SDK 已具备）
2. `ChatProfile.tsx` 按原视觉（ListItem）增补（仅群聊显示）：「群聊名称」「群公告」编辑项，弹窗复用现有样式，保存走 updateChatProfile，成功后刷新 chat
3. 好友备注/星标：`ContactService` 新增 `updateContactPreferences(targetUserId, {remark?, isStarred?})` → `social.contacts.preferences.update`；`ChatProfile` 对单聊（direct）按原视觉增补「设置备注」项（目标用户取自 participants）
4. 黑名单接线：`SystemSettings.tsx`（Blacklist 页）本地假数据 → 真实数据（`contacts.list` 过滤 `isBlocked`）+ 移除走 `contacts.preferences.update({isBlocked:false})`，页面结构与视觉不变
5. 清空聊天记录：后端无契约（PC 亦无），维持现有 toast 提示

## 四、通讯录补齐
1. **组织架构接入真实 API**（核心）：`OrganizationService.ts` 从 mock 切换为 `@sdkwork/iam-app-sdk`（`iam.organizations.list` / `iam.departments.list` / `iam.departmentAssignments.list`），参照 PC 端 `OrganizationDirectoryService` 的解包/分页/降级模式，适配现有 `OrgDepartment/OrgMember/Organization` 类型；`searchMembers` 无真实接口时对已加载成员做本地过滤。OrganizationList/OrganizationDetail 页面代码零视觉改动
2. **群聊列表**：AddressBook「群聊」入口 toast → 新增轻量群聊列表页（完全复用 `ChatListItem` 视觉，`conversations.list` 过滤 `conversationType==='group'`），在 shell 路由目录注册
3. **标签/公众号**：后端无标签-联系人关系契约、无公众号能力，保持 toast（与现状一致）

## 五、实时与数据层完善
1. 好友申请实时刷新：`NewFriends.tsx` 挂载时订阅 user scope（`subscribeScopeEvents('user', currentUserId)`）监听 `friend_request.*` 事件 → 刷新列表；`AddressBook` 联系人列表同理由 friend 事件驱动刷新（复用现有 `chatRealtimeService`，无需改实时层）
2. 确认会话激活时自动已读（现有 load 流程已覆盖，保持）

## 六、验证与打磨
- 逐项执行类型检查：`pnpm --filter sdkwork-im-h5-chat --filter sdkwork-im-h5-contacts ... typecheck`（或 H5 app 的 `pnpm check` 等效命令，实施时按包脚本确认）
- 运行现有单测（如 `ContactService.test.ts` 所在包的测试命令）
- 若本地后端可用（im-api-base-url 127.0.0.1:4178），启动 `pnpm dev` 进行端到端手工验证：发图片/文件、撤回/编辑、备注、群资料、组织架构、黑名单、好友申请实时刷新；不可用时报告受阻点
- 按 `../sdkwork-specs/CODE_STYLE_SPEC.md`、`FRONTEND_CODE_SPEC.md`、`TEST_SPEC.md` 对齐代码规范

## 范围外（保持现状）
- 后端契约缺失：清空聊天记录、消息转发、公众号/小程序、标签-联系人关系、扫码
- 语音/视频通话真实信令、聊天背景、展示设置（showAvatar/cleanMode）等本地能力
- 不触碰 PC 端、不修改 OpenAPI/proto 契约、不重写任何页面样式
