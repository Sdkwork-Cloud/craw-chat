# 收藏放 sdkwork-cms 的完整实现方案

## 〇、架构定位:为什么 CMS 是"集成多业务模块"的正确落点

深入调研 `../sdkwork-cms` 后确认:CMS 的架构 DNA 就是**跨对象聚合**——
- `cms_feed_item` 可引用 entry/page/**external_url** 三种目标 + `item_kind` + 运营快照字段(operator_title/summary/media_json);
- `cms_page_block.ref_type/ref_id`、`cms_publish_snapshot.owner_type/owner_id` 多态引用惯例成熟;
- CMS app SDK 已是"consumer-sdk"模式(依赖 IAM login-context + Drive media-upload),天生可携带登录态。

**收藏 = 用户 × 跨业务域内容对象**。放 CMS 后:
- `target_type` 维度集成多个业务模块:IM 消息(im_message)、云盘文件(drive_file)、知识库文章(kb_article)、CMS 条目(cms_entry)、外部链接(external_url)……**新来源只需新增 target_type 值,无需新建服务**;
- `favorite_type` 维度(link/article/image/file/voice/chat)驱动 h5 页面 7 个筛选 Tab,与页面设计一一对应;
- 依赖方向干净:IM h5 前端组合消费 `sdkwork-cms-app-sdk`(与 h5-core 已组合的 7 个 sibling SDK 完全同模式);后端无 IM→CMS / CMS→IM 依赖;收藏详情以快照自足,不复制任何他域表。

> 说明:此方案使收藏权威从 IM 的 messages.favorites(聊天域)迁移至 CMS(内容域)。IM 现有 API **保留不删除**作兼容,新代码全部走 CMS(详见 §三)。

## 一、sdkwork-cms 仓库改动(跨仓)

### 1. 数据库:新表 `cms_favorite`(baseline-plus-migrations,新迁移 0002)

```sql
-- database/migrations/postgres/0002_cms_favorite.up.sql
-- (带 -- sdkwork:migration header,格式同现有 0001)
CREATE TABLE IF NOT EXISTS cms_favorite (
    id                   BIGINT PRIMARY KEY,
    uuid                 VARCHAR(64) NOT NULL UNIQUE,
    tenant_id            BIGINT NOT NULL,
    organization_id      BIGINT NOT NULL DEFAULT 0,
    user_id              BIGINT NOT NULL,          -- 收藏者(用户维度)
    favorite_type        VARCHAR(32) NOT NULL      -- link/article/image/file/voice/chat
                         CHECK (favorite_type IN
                           ('link','article','image','file','voice','chat')),
    target_type          VARCHAR(64) NOT NULL      -- im_message/drive_file/kb_article/cms_entry/external_url
                         CHECK (btrim(target_type) <> ''),
    target_id            BIGINT NOT NULL DEFAULT 0, -- 域内对象 id(im_message 时=消息 id)
    target_uuid          VARCHAR(64),
    target_url           VARCHAR(2048),            -- external_url 目标
    title                VARCHAR(512) NOT NULL DEFAULT '',
    summary              VARCHAR(2048) NOT NULL DEFAULT '',  -- content_preview
    source_display_name  VARCHAR(256) NOT NULL DEFAULT '',
    media_json           JSONB NOT NULL DEFAULT '{}',
    favorited_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    version              BIGINT NOT NULL DEFAULT 0,  -- 乐观锁
    deleted_at           TIMESTAMPTZ,
    deleted_by           BIGINT NOT NULL DEFAULT 0,
    CONSTRAINT uk_cms_favorite_user_target UNIQUE
        (tenant_id, organization_id, user_id, target_type, target_id)
);
CREATE INDEX idx_cms_favorite_user_ts  ON cms_favorite
    (tenant_id, organization_id, user_id, favorited_at DESC);
CREATE INDEX idx_cms_favorite_user_type ON cms_favorite
    (tenant_id, organization_id, user_id, favorite_type, favorited_at DESC);
```

要点:UK(user,target)保证**幂等**(重复收藏同一对象=刷新置顶,微信语义);软删 `deleted_at`;快照字段(title/summary/source/media_json)使列表页零依赖目标域;无外键(跨域目标,快照自足)。契约登记 `database/contract/schema.yaml` + `table-registry.json`(bounded_context: content, write_owner: sdkwork-content-cms-service),跑 `pnpm db:validate / db:materialize:contract / db:plan`。

### 2. API(app 面,dual-token 登录态)

```
POST   /app/v3/api/cms/favorites                {targetType,targetId,favoriteType,title,summary,sourceDisplayName,targetUrl?}
GET    /app/v3/api/cms/favorites?favoriteType&pageSize&cursor&q     → {items, pageInfo}
DELETE /app/v3/api/cms/favorites/{favoriteId}
```
- 操作 id:`cms.favorites.create/list/delete`,注册进 `docs/api/cms-v1-operation-registry.json`;
- `apis/app-api/content/cms-app-api.openapi.json` 追加 3 条 path + components(CmsFavoriteView/CreateCmsFavoriteRequest/CmsFavoriteListResponse)——securitySchemes 已有 AuthToken+AccessToken(dual-token),`crates/sdkwork-routes-cms-app-api/src/http_route_manifest.rs` 已支持 `dual-token` auth_mode 映射(已验证),OpenAPI 的 security 声明 `[AuthToken, AccessToken]`。

### 3. 代码(严格照 CMS 现有分域模式)

| 层 | 文件 |
|---|---|
| 服务用例 | `crates/sdkwork-content-cms-service/src/service/favorites.rs` + `domain/` 模型 + `ports/repository.rs` trait 方法 + `service/mod.rs` 注册 |
| 仓库 | `crates/sdkwork-content-cms-repository-sqlx/src/repository/favorites.rs` + `mod.rs` + `port_impl.rs`(sqlx,`WHERE tenant_id=$1`、软删、乐观锁,照 entries.rs 模式) |
| 路由 | `crates/sdkwork-routes-cms-app-api/src/{paths.rs,manifest.rs,routes.rs,lib.rs,handlers.rs}` + `crates/sdkwork-cms-http-handlers`(app 面首组需登录操作;key 分页 + favorite_type/q 筛选照 feeds 的 list 模式) |
| 权限 | `docs/security/cms-v1-permission-registry.json` 补 `cms.favorites.*`(app 面) |
| 集成注册 | `docs/integration/cms-v1-integration-registry.json` 补 favorites 端口说明 |

### 4. SDK 生成
改完 app-api OpenAPI 后:同步 `sdks/sdkwork-cms-app-sdk/openapi/*.sdkgen.yaml` → 运行生成器 `../sdkwork-sdk-generator/bin/sdkgen.js`(生成器路径已在该 sdkgen.yaml 注释中确认)→ 产出 `sdkwork-cms-app-sdk-typescript`(带 IAM login-context 依赖,天然对接登录态)→ `pnpm verify` + `pnpm api:assembly:materialize`。

### 5. 测试
`cargo test -p sdkwork-content-cms-service` + http-handlers 集成测试(create→list(带 favoriteType/q/cursor)→delete 流程,照 IM 测试风格)+ `pnpm db:contract:check / db:plan / db:drift:check`。

### 3. user 包:收藏数据接真实逻辑
- 新增 `packages/sdkwork-im-h5-user/src/services/FavoriteService.ts`:

  - `removeFavorite(favoriteId)` → `favorites.delete`;`createFavorite(...)`(供星标调用复用);
  - 工厂 + 可注入客户端(`createFavoriteService(resolveClient = getCmsAppSdkClient)`);
- 改造 `FavoritesPage.tsx`:仅将 `FAVORITES` mock 常量替换为 service 加载(useEffect + state),搜索/筛选/长按/ActionSheet 交互逻辑原样保留;删除 → 真实 `removeFavorite` + 本地移除 + 现有 toast;分享 → 保持 toast;**不新增任何视觉元素**;
- i18n:补 `user.favorites.title`(zh/en,routeCatalog titleKey),现有 `user.auto_*` 不动。

### 4. chat 包:星标动作收口 CMS(真实逻辑闭环)
`packages/sdkwork-im-h5-chat/src/services/ChatService.ts` `starMessage`:
- 收藏 → CMS `favorites.create`,`target_type: "im_message"`,`target_id: messageId`,`favoriteType` 按消息内容推导(文本→chat、图片→image、文件→file、语音→voice、链接→link,article 预留给未来转发文章),快照 title/preview/sourceDisplayName 照现有取值;
- 取消收藏 → CMS `favorites.list(targetType=im_message)` 游标扫描匹配后 delete(保留现有防重复游标断言)。
