# 收银台 + 订单中心实现计划（sdkwork-order H5 实现，sdkwork-im 集成）

## 调研结论（已完成）

**后端已完整可用，无需修改 Rust**：
- `sdkwork-order` Rust 服务已实现：checkout session 三步下单、订单列表/详情/统计、`POST /orders/{orderId}/payments`（mobile_cashier_h5 返回 `payment_params{cashierUrl, qrCodePayload, nextAction, orderSn, cashierScene}`）、`GET /payment_success`（{paid,status,statusName}）、取消、券码核销、充值、会员订单；paymentMethod 必填且仅允许 `wechat_pay | alipay | balance`（order_router.rs:40）；金额为最小单位字符串；订单状态 wire 值 `pending_payment/paid/fulfilled/completed/cancelled/expired/refunding/refunded`。
- `sdkwork-payment` 经共享库链接进 order 网关；webhook 归属 order 域。
- 生成 SDK `@sdkwork/order-app-sdk`（SdkworkAppClient + createClient，dual-token）已存在于 `sdks/`，`sdkwork-im/pnpm-workspace.yaml` 已注册（L72）。

**前端差距（本次实现的主体）**：
- `sdkwork-order-mobile-react-orders`（规范移动端 H5 订单包）：OrderCenter/OrderDetail/VoucherCodePage 全是 `CapabilityUnavailablePage` 占位；OrderService 全部抛 `OrderCapabilityUnavailableError`；组件（OrderCard/OrderTabsNav/OrderActionButtons/OrderInfoCards/OrderItemsCard 等）已写好但未接线；**无收银台页面**。
- `sdkwork-im-h5`：`im-h5-orders` 适配器（re-export 规范包）存在但**零运行时引用**；shell 模块注册表/路由目录无 orders；`moduleCatalog.ts` 将 orders 标记为 CONTRACT_PENDING；bootstrap 未建 order SDK 客户端。
- 已核对 OpenAPI/Rust 读模型：订单列表项 `{order_id, order_sn, status, status_name, subject, total_amount(字符串), paid_amount?, discount_amount?, quantity, created_at, pay_time?, expire_time?, payment_method?}`，详情加 `items[{id, product_name, quantity, unit_price, total_amount}]` + `out_trade_no?` + `transaction_id?`。前端 `Order` 模型必须按此对齐（旧模型的 shopName/address/shippingFee/image/specs 后端不存在）。

## 决策（推荐方案，按架构规范）

1. **收银台形态**：站内收银台页面（sdkwork-order 移动包内）：金额展示 + 支付方式选择（wechat_pay/alipay/balance，与后端 ALLOWED_PAYMENT_METHODS 严格对齐）+ 二维码（内容=qrCodePayload/cashierUrl）+ 倒计时（min(expire_time, 15min TTL)）+ 3s 轮询 payment_success 的完整状态机（支付中/成功/失败/已取消/已过期/重新支付）+“在浏览器打开外部收银台”兜底按钮。
2. **IM 入口**：orders 加入默认模块组合，TabBar 新增“订单”Tab（/orders）；另保留 /orders/:orderId、/orders/:orderId/cashier、/orders/voucher 直达路由。
3. **动作对齐后端**：订单详情/列表仅渲染后端支持的动作（待付款→付款/取消订单）；移除 confirmReceipt/review/remindShipping/modifyAddress/deleteOrder/applyRefund 等无后端端点的操作（含删除 OrderReviewModal、OrderAddressCard 两个无数据源组件）。
4. 遵循积木架构：所有订单 UI/服务在 sdkwork-order 仓库实现；sdkwork-im 只做适配器+shell 路由+SDK 客户端注入（仿 drive 的 CloudDriveService 运行时注入模式）。

## 明确不做（边界）
- 不改 Rust 后端（现有 API 已完整覆盖收银台与订单流转，无缺失端点）。
- sdkwork-shop 的购物车/商品浏览/下单入口属 shop 域，本次不实现；`OrderService.createOrder`（checkout 三步）接口已为未来购物流程预留。
- 不做 PC 端改动；不接外部 cashierUrl 站点开发（仅提供兜底打开按钮）。
- 支付真实扣款依赖 provider 配置；开发环境后端已有 provider-unavailable 降级（返回本地收银台参数），前端流程不受影响。
