## Evidence Sync Contract

The release evidence sync script is:

```text
scripts/release/sync-sdkwork-im-release-evidence.mjs
```

It reads package data from:

- `dist/release-packages/release-packages-manifest.json`
- package archives under `dist/release-packages/`
- adjacent package manifests under `dist/release-packages/*.manifest.json`
- evidence files under `dist/release-evidence/<package-id>/`

Supported evidence file names are based on the package archive file name:

- signing: `<archive>.sig`, `<archive>.asc`, `<archive>.sigstore.json`,
  `<archive>.minisig`, or `<archive>.p7s`
- SBOM: `<archive>.cdx.json` or `<archive>.spdx.json`
- provenance or attestation: `<archive>.intoto.jsonl`,
  `<archive>.attestation.jsonl`, or `<archive>.provenance.json`

The script fails closed when any selected enabled direct distribution package
lacks a release archive, adjacent package manifest, signature evidence, SBOM
evidence, or provenance/attestation evidence. It preserves published package
URLs and writes only package checksum, size, artifact refs, signing refs, SBOM
refs, and provenance refs.

## Commercial Readiness Blockers

SDKWork IM is still not commercially releasable in this loop.

The new evidence synchronization workflow is a safe ingestion path for real
release artifacts; it is not a substitute for producing those artifacts or their
security evidence. Current blockers remain:

- no real `dist/release-packages/release-packages-manifest.json` for the active
  13-package matrix;
- no real package archives for the active 13-package matrix;
- no real package signatures while `security.signatureRequired=true`;
- no real SBOM files while `security.sbomRequired=true`;
- no real provenance or attestation files while `security.sbomRequired=true`;
- `chat-primary-icon`, `chat-web-screenshot`, and `chat-catalog-preview` still
  carry `metadata.generatedPlaceholder=true` in `sdkwork.app.config.json`.
