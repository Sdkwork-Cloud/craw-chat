# SDKWork IM 源码部署

本文说明如何在服务器上通过 `pnpm` 从源码构建和启动 SDKWork IM。源码部署会在仓库内生成构建产物，但不会创建安装包或发布压缩包。

## 适用范围

- 受控的开发、测试和私有部署主机
- 需要直接验证当前提交的集成环境
- 由运维人员管理依赖、配置、密钥和进程生命周期的服务器

正式发布仍应优先使用经过校验的 server 安装包。不要在生产主机上执行未经审核的分支或自动拉取远程代码。

## 目录与产物

```text
源码目录: /opt/sdkwork/chat-src
配置目录: /etc/sdkwork/chat
数据目录: /var/lib/sdkwork/chat
日志目录: /var/log/sdkwork/chat
运行目录: /run/sdkwork/chat
后端产物: target/release/sdkwork-im-server
前端产物: apps/sdkwork-im-pc/dist
```

## 环境准备

```bash
corepack enable
pnpm --version
rustc --version
cargo --version
node --version
```

安装依赖时使用锁文件：

```bash
cd /opt/sdkwork/chat-src
pnpm install --frozen-lockfile
```

## 运行配置

源码部署读取 `/etc/sdkwork/chat/server.env`。应用配置使用 `SDKWORK_IM_*`，数据库连接只使用统一的 `SDKWORK_DATABASE_*`。

```env
SDKWORK_IM_ENVIRONMENT=production
SDKWORK_IM_DEPLOYMENT_PROFILE=standalone
SDKWORK_IM_RUNTIME_TARGET=server
SDKWORK_IM_APPLICATION_PUBLIC_HTTP_URL=https://chat.example.com

SDKWORK_DATABASE_ENGINE=postgresql
SDKWORK_DATABASE_HOST=postgres.internal.example.com
SDKWORK_DATABASE_PORT=5432
SDKWORK_DATABASE_NAME=sdkwork_ai_prod
SDKWORK_DATABASE_SCHEMA=sdkwork_ai_prod
SDKWORK_DATABASE_USERNAME=sdkwork_ai_prod
SDKWORK_DATABASE_PASSWORD_FILE=/etc/sdkwork/chat/database.secret
SDKWORK_DATABASE_SSL_MODE=require
SDKWORK_DATABASE_MAX_CONNECTIONS=20
```

同一部署中的 IAM、Drive、IM、Knowledgebase 和 Commerce 模块共用 `sdkwork_ai_prod` database/schema。源码部署不得生成应用或模块私有的数据库键。

## 构建计划

先查看不含 secret 的构建计划：

```bash
pnpm run deploy:source:plan
```

执行 server 源码构建：

```bash
pnpm run build:server:source
```

构建过程必须使用根脚本和仓库锁文件。不要绕过标准脚本手工拼接 Cargo、Vite 或 SDK 生成命令。

## 数据库准备

首次部署或 migration 变更后执行受控数据库生命周期命令：

```bash
pnpm db:postgres:plan
pnpm db:postgres:migrate
```

生产数据库初始化需要管理员凭据时，通过受限 secret 文件或部署平台临时注入 `SDKWORK_DATABASE_ADMIN_*`，执行完成后立即移除。

## 启动

```bash
pnpm run start:server:source
```

该命令读取 `/etc/sdkwork/chat/server.env`，启动 release 构建的 server，并保留公开 HTTP URL 的单一权威 `SDKWORK_IM_APPLICATION_PUBLIC_HTTP_URL`。

## systemd 示例

```ini
[Unit]
Description=SDKWork IM source deployment
After=network-online.target

[Service]
Type=simple
User=sdkwork
Group=sdkwork
WorkingDirectory=/opt/sdkwork/chat-src
EnvironmentFile=/etc/sdkwork/chat/server.env
ExecStart=/usr/bin/pnpm run start:server:source
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

## 验证

```bash
pnpm run test:source-server-deploy
curl --fail --silent https://chat.example.com/health
curl --fail --silent https://chat.example.com/ready
```

验证内容包括：构建提交、数据库 migration 状态、process-shared pool、公开 URL、Redis、日志目录权限和优雅关闭。

## 更新与回滚

1. 在独立工作区检出目标提交并执行标准检查。
2. 备份数据库并记录当前 migration version。
3. 执行 `pnpm install --frozen-lockfile` 和 `pnpm run build:server:source`。
4. 停止旧进程，切换到已审核提交，再启动并验证 readiness。
5. 失败时回到上一审核提交；数据库变更按 migration 的 forward-fix/恢复方案处理，不手工删除 schema。

源码目录中不得保存生产 dump、数据库密码、token、私钥、运行日志或用户上传文件。
