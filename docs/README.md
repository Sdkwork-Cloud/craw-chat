# SDKWork IM Documentation

Status: active
Owner: `im-platform`
Updated: 2026-07-23
Specs: `DOCUMENTATION_SPEC.md`, `SDKWORK_WORKSPACE_SPEC.md`

This directory is the human documentation layer for SDKWork IM. Machine contracts remain in
`specs/`, authored HTTP contracts remain in `apis/`, and generated SDK workspaces remain in `sdks/`.

## Canon

| Area | Entry | Purpose |
| --- | --- | --- |
| Product | [product/prd/PRD.md](product/prd/PRD.md) | Product scope, users, outcomes, and release posture |
| Technical architecture | [architecture/tech/TECH_ARCHITECTURE.md](architecture/tech/TECH_ARCHITECTURE.md) | Current module, runtime, API, SDK, persistence, and security boundaries |

The Canon describes only the current architecture. Superseded designs remain discoverable through
the archive or their explicit requirement, ADR, and migration records; they do not override Canon.

## Contract Inventories

| Inventory | Source authority | Contents |
| --- | --- | --- |
| [HTTP API inventory](api-reference.md) | Three authored OpenAPI documents under `apis/` | Complete method, path, and `operationId` list for IM-owned Open, App, and Backend APIs |
| [Database inventory](database-design.md) | `database/contract/table-registry.json` | Complete list of IM-owned tables, profiles, owners, and migration sources |

Both inventories are generated by `sites/scripts/generate-contract-inventories.mjs`. They exclude
gateway-mounted APIs and database objects owned by sibling SDKWork applications.

## Active And Archive Boundary

`docs/archive/` is the explicit read-only history boundary. The pre-Canon directories
`docs/架构/`, `docs/step/`, `docs/review/`, and `docs/superpowers/`, plus unlinked legacy
`TECH-*` shards, are retained only for stable historical links until a controlled archive move.
They are not active architecture authority, must not be added to product navigation, and must not
receive new design work. New documents use the standard paths listed above.
